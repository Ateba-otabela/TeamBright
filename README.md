# TeamBright — CamerHitz

**CamerHitz** is a music-industry platform created by TeamBright for the CIMFEST 2026 demo in Cameroon. It helps artists and music professionals manage releases, understand song performance, connect with industry partners, and coordinate events from one studio experience.

## Project Links

- **GitHub repository:** [Ateba-otabela/TeamBright](https://github.com/Ateba-otabela/TeamBright)
- **Live demo:** A public deployment link has not been provided yet.

## What CamerHits Does

- **Artist and industry profiles:** Accounts and role-based experiences for artists, DJs, broadcasters, promoters, fans, and administrators.
- **SoundDNA Analyzer:** Compare a studio demo with a musical benchmark and review readiness scores, dimensions, and suggested improvements.
- **Canary release monitoring:** Record weekly release performance and review momentum, trajectory, and advisor insights.
- **Music discovery:** Publish songs and make active releases available for discovery and playback.
- **Phone Broadcast:** Select a track and a DJ, radio station, or TV destination for direct promotion outreach.
- **Collaborator and split workflows:** Manage collaborator information and release split agreements.
- **Events and ticketing:** Create events, manage ticket tiers and collaborators, issue QR tickets, record sales, and validate tickets at the gate.
- **Verification and administration:** Submit professional verification requests and manage review decisions.

> **Analysis note:** The current Analyzer and Canary recommendations use audio signal processing and deterministic rules. They are not generated by a hosted generative-AI service.

## Technology Stack

| Area | Technologies |
|---|---|
| Frontend | React 19, JavaScript, Vite, HTML, CSS |
| Backend API | Python, FastAPI, Pydantic, SQLModel, SQLAlchemy, Uvicorn |
| Audio analysis | Librosa, NumPy, SoundFile |
| Database | SQLite by default; PostgreSQL supported through `DATABASE_URL` |
| Authentication | Signed JWT access tokens and salted PBKDF2 PIN hashes |
| Ticketing | QR code generation and signed ticket tokens |
| Frontend dependencies | npm (`npm install` using `Frontend/package.json`) |
| Development assistants | OpenAI Codex and GitHub Copilot |

## Getting Started

### Requirements

- Node.js and npm
- Python 3.11 or newer

### Install frontend dependencies

From the repository root:

```bash
cd Frontend
npm install
npm run dev
```

This starts the React/Vite frontend development server. For the backend-served studio experience, start the API as described below.

### Install and run the backend

From the repository root, in PowerShell:

```powershell
cd Backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:NUMBA_DISABLE_JIT = "1"
python seed_demo.py
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Then open:

- Studio: [http://127.0.0.1:8000](http://127.0.0.1:8000)
- Interactive API documentation: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

The `NUMBA_DISABLE_JIT` setting works around a Librosa/Numba issue that may occur on Windows with Python 3.13. Stop the backend with `Ctrl+C`.

## Configuration

The backend reads configuration from environment variables or `Backend/.env`:

| Variable | Default | Description |
|---|---|---|
| `DATABASE_URL` | `sqlite:///./sounddna.db` | Database connection URL; can be set to PostgreSQL. |
| `JWT_SECRET` | Development-only value | JWT signing secret. Use a private strong value outside local development. |
| `JWT_ALGORITHM` | `HS256` | JWT signing algorithm. |
| `ACCESS_TOKEN_MINUTES` | `60` | Access-token lifetime. |
| `ENV` | `development` | Environment label. |
| `DEMO_PIN` | `1234` | PIN used by the general demo seed script. |

Keep real secrets out of source control. Demo accounts and sample data are for local demonstration only.
